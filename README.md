their upstream and downstream neighbours (graph learning) than models that treat every road
segment on its own?

This branch, `phase2-deep-learning`, holds the deep-learning phase and only what it needs to train,
predict, be compared fairly and be shown. The complete Phase 1 work (EDA, preprocessing notebooks,
random forest, tuning, feature ablation, LaTeX report and slides) is on `main`.

## 1. Results

Test MAE in mph on the last 24 days (6,901 forecast windows, 88% of target cells scored after masking
outages). Deep-learning rows are seed 42. Lower is better.

| Model | 5 min | 15 min | 30 min | 60 min |
|---|---|---|---|---|
| Persistence (last reading) | 2.82 | 3.49 | 4.19 | 5.35 |
| Seasonal average | 4.18 | 4.18 | 4.18 | 4.18 |
| XGBoost | 2.31 | 2.84 | 3.26 | 3.69 |
| XGBoost + neighbour features | 2.23 | 2.76 | 3.18 | 3.65 |
| GRU, time only | 2.32 | 2.83 | 3.22 | 3.63 |
| ST-GAT with every edge removed | 2.31 | 2.81 | 3.19 | 3.57 |
| **ST-GAT** | 2.22 | 2.67 | **3.04** | **3.46** |
| DCRNN | **2.21** | **2.67** | 3.05 | 3.49 |

* **The graph is what helps.** The same ST-GAT with its edges removed (same parameters, same training)
  is 3–5% worse at every horizon; the day-block bootstrap interval excludes zero, and the spread over
  three seeds is about 0.01 mph.
* **A neural network without the graph only ties XGBoost.**
* **ST-GAT vs XGBoost + neighbours at 60 min:** 5.3% lower MAE (95% CI 4.3–6.2). In rush hour 8.6%, off-peak 3.4%.
* **ST-GAT and DCRNN are tied up to 30 minutes;** ST-GAT is slightly ahead at 60.
* **The graph helps at 76% of sensors** (per-sensor 60-min MAE).

**Report (IEEE format, PDF):** [`report/main.pdf`](report/main.pdf). **Presentation:** [`deep_learning/presentation/index.html`](deep_learning/presentation/index.html) (interactive) and [`deep_learning/presentation/presentation.pdf`](deep_learning/presentation/presentation.pdf) (same 16 slides as PDF).

Full tables (RMSE, MAPE, seeds, peak/off-peak, bootstrap intervals, literature check):
[`reports/dl_results_summary.md`](reports/dl_results_summary.md), generated by notebook 14.

## 4. Data

METR-LA: 207 loop detectors on Los Angeles freeways, average speed every 5 minutes,
1 March – 27 June 2012 (34,272 steps). A reading of 0 mph means the sensor was down (8.1% of all cells;
2,148 steps where every sensor is down).

```bash
python -m deep_learning.prepare_data --download   # fresh machine: download + checksum + build
python -m deep_learning.prepare_data              # raw files already in data/raw/
```

This downloads four files into `data/raw/` (the speed table from a Hugging Face mirror, the sensor ids,
locations and road distances from the DCRNN GitHub repository), checks their SHA-256, and writes
`data/processed/`: the cleaned speed table, the adjacency matrix and the road-distance matrix.
It recomputes the split and scaler and **checks** them against the committed `splits.json` and
`scaler.json` instead of overwriting them, so every machine uses exactly the same data.
Sources, sizes and checksums: [`data/README.md`](data/README.md).

Raw and processed data are not committed (about 70 MB); only the small json/csv contract files are.

## 6. Training the deep-learning models

### On a Kaggle GPU (what produced the results)

1. Create a Kaggle API token (kaggle.com → Settings → API → Create New Token) and save it as
   `~/.kaggle/access_token` with `chmod 600`. Never commit it.
2. Commit and push your branch: the Kaggle job clones exactly the current commit from GitHub.
3. Push the jobs (they are private, use a Tesla T4 and turn internet on to download the data):

```bash
# hyper-parameter search, validation only: 12 runs, 25 epochs each (~3 h)
python -m deep_learning.kaggle.launch push --slug metr-dl-search --models st_gat st_gat_noedge \
    -- --lr 0.0003 0.001 0.003 --width 64 128 --max-epochs 25

# DCRNN, default size (~1.5 h)
python -m deep_learning.kaggle.launch push --slug metr-dl-dcrnn --models dcrnn

# final runs at the chosen setting, three seeds each (~4 h)
python -m deep_learning.kaggle.launch push --slug metr-dl-final --models gru st_gat st_gat_noedge \
    --seeds 42 1 2 -- --lr 0.001 --width 128
```

4. Check and fetch:

```bash
python -m deep_learning.kaggle.launch status --slug metr-dl-final
python -m deep_learning.kaggle.launch fetch  --slug metr-dl-final   # copies models, predictions, histories into artifacts/
```

Kaggle runs one GPU session at a time, so later jobs wait in the queue. The log becomes available
only when a job finishes; `fetch` saves it as `artifacts/metrics/kaggle_<slug>.log`.
Measured on the T4 per epoch: GRU ~34 s, no-edge twin ~42 s, ST-GAT ~56 s, DCRNN ~159 s.

### Locally

```bash
python -m deep_learning.train --models st_gat --seeds 42 --lr 0.001 --width 128
python -m deep_learning.train --models gru st_gat st_gat_noedge --seeds 42 1 2 --lr 0.001 --width 128 --device mps
```

| Flag | Meaning |
|---|---|
| `--models` | any of `gru`, `st_gat`, `st_gat_noedge`, `dcrnn` |
| `--seeds` | one run per seed (default 42) |
| `--lr`, `--width` | several values = grid search; runs are then named `..._lr{lr}_w{width}` |
| `--max-epochs` | default 60 (early stopping, patience 10) |
| `--tag` | suffix for the run name |
| `--device` | `cuda`, `mps` or `cpu` (default: best available) |

Each run writes `artifacts/models/dl_<model>_s<seed>.pt`, `artifacts/metrics/dl_<model>_s<seed>_history.csv`
and `_summary.json`, and validation/test predictions at 5/15/30/60 min. Locally on an 8 GB M3 it is
3–5× slower than the T4 (ST-GAT ~1.6 min per epoch, DCRNN ~8 min per epoch).

## 12. How the experiment is designed

* **Split:** chronological, cut at midnight: 83 days train / 12 validation / 24 test (about 70/10/20%,
  the usual METR-LA proportions, but on whole days so no day is split). Never random. Memorial Day falls in validation.
* **Windows:** 12 input steps (60 min) for every model; forecasts 1–12 steps ahead, reported at 5/15/30/60 min.
* **Inputs per sensor and step:** scaled speed, observed flag, sin/cos time of day, sin/cos day of week.
* **Missing data:** zeros are outages. Inputs carry the observed flag; missing targets get no loss and are never scored.
* **Scaling:** z-score fitted on training rows only.
* **Target:** the change from the last observed speed (persistence), so a model's output of zero is already a sensible forecast.
* **Loss:** masked MAE. Optimiser AdamW, lr 1e-3, learning rate halved after 3 flat epochs, gradient clipping 5, early stopping on validation MAE with patience 10, best-epoch weights kept.
* **Fair scoring:** same test windows for all models; a target counts only if it was observed and every model produced a forecast (common mask); predictions clipped to 0–70 mph.
* **Peak:** weekdays 07–10 and 15–19 at the forecast target time, fixed before training.
* **Uncertainty:** day-block bootstrap (2,000 resamples of the 24 test days) and three seeds.
* **Graph:** DCRNN's thresholded Gaussian kernel on road distances: 1,515 directed edges, only 27% reciprocal, never symmetrised.

## 13. Models

| Model | Idea | Parameters |
|---|---|---|
| Persistence | repeat the last observed speed | 0 |
| Seasonal average | mean speed for that weekday and time slot | – |
| XGBoost | trees on each sensor's lags, rolling stats, calendar | – |
| XGBoost + neighbours | same plus upstream/downstream neighbour speeds as columns | – |
| GRU | one GRU shared by all sensors + a sensor embedding; no sensor sees another | 158 k |
| ST-GAT | GRU summary per sensor, then 2 layers of graph attention (separate upstream and downstream, road weight as edge feature) | 328 k |
| ST-GAT, edges removed | identical network and parameter count, no edges: isolates what the graph adds | 328 k |
| DCRNN | GRU whose matrix products are diffusion convolutions on the directed graph (2 hops each way), encoder–decoder with teacher forcing | 380 k |

## 14. Decisions and what was rejected

* **83/12/24 days** rather than a random split (leaks the future through overlapping windows) or a
  plain 70/10/20 cut by row (splits days in half).
* **Kaggle T4** rather than training locally: 3–5× faster and does not tie up the laptop.
* **ST-GAT and DCRNN** as the graph models (the brief's GAT or diffusion model, fixed adjacency).
  **Graph WaveNet** (learned adjacency, dilated convolutions) was considered and not built: the
  ablation already answers the question and both graph models are within the published range.
* **Other options considered in the plan:** STGCN, ASTGCN, AGCRN, MTGNN, GMAN, TCN, LSTM and
  Transformer models; not built because of directed-graph support, size or the time budget.
  The reasoning for each is in the approved plan.
* **Learning rate and width** searched on validation for both ST-GAT and its no-edge twin so the
  ablation is not decided by tuning; both chose lr 1e-3, width 128.

The visual plan with the full reasoning was approved before any code was written.

## 15. Limits

* One city, 119 days in 2012, speed only. No claim beyond METR-LA.
* The Phase 1 XGBoost models were re-run so every model is scored on identical points; the re-runs
  are 0.01–0.05 mph worse than the numbers committed on `main` (cause not traced).
* DCRNN is our re-implementation with one seed, not the authors' code.
* Literature numbers use different splits and masks: a sanity check, not a leaderboard.
* Attention weights show where the model looks, not why it is right.
* Nothing controls real traffic; signal control is simulated only.

## 16. Troubleshooting

| Problem | Fix |
|---|---|
| `FileNotFoundError ... run python -m deep_learning.prepare_data first` | run step 1 of section 5 |
| `import xgboost` fails on macOS | `brew install libomp` |

| DCRNN very slow locally | expected (~8 min per epoch on an M3); use Kaggle |
